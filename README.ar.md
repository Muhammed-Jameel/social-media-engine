## ما هو هذا المشروع

تم تصميم محرك وسائل التواصل الاجتماعي كطبقة آمنة متدرجة بين إنشاء المحتوى المساعد بالذكاء الاصطناعي والنشر الفعلي على الشبكات.

يربط بين:

1. طبقة إنشاء محتوى متوقعة وقابلة لإعادة الإنتاج.
2. موافقات بشريّة في حلقة المراجعة.
3. ضوابط نشر منظمة مع تتبع فريد ومعرّف عدم تكرار الطلبات.
4. موصلات مزوّدين معطلة افتراضيًا.

---

## من يجب أن يستخدمه

أي شخص يحتاج لتشغيل وسائل التواصل الاجتماعي على نطاق متوسط:

1. فرق التسويق الصغيرة.
2. الشركات ذات الشخص الواحد.
3. المستقلون الذين يديرون عدة حسابات.
4. الوكالات ومقدمو الخدمات ذوو تدفق عمل متكرر.

---

## ما الذي يفعله

- ينشئ خطط شهرية ومخرجات للمشاركات بناءً على أدلة العلامة واستراتيجيات الإدخال.
- ينشئ مسودات ثنائية اللغة (عربي + إنجليزي) عبر سيرات عمل محددة وقابلة للتكرار.
- يدعم كل مزوّدي الوسائط الاجتماعية الرئيسية، مع مسارات أساسية لـ Instagram وFacebook وTikTok.
- يشغّل سيرات عمل جودة تشمل مراجعات الإبداعية وفحوصات الأصالة.
- يخزن نية النشر، الموافقات، المعرفات، الـ hashes، وثائق الامتثال، وحالة التنفيذ.
- يوفر لوحة تحكم لفحص كل خطوة واعتمادها قبل النشر.
- يدعم النشر المراقب عبر جسر Postiz المستضاف ذاتيًا.
- يحافظ على إعدادات افتراضية غير مدمرة لكي يراجع الفريق العمل بأمان قبل الإطلاق.

## البدء السريع

### 0) رابط المشروع

- المستودع العام: [social-media-engine](https://github.com/Muhammed-Jameel/social-media-engine)

### 1) المتطلبات

1. Node.js `22.13+` (المستودع يستخدم `22.23.2` في `.nvmrc`)
2. pnpm `11.19.0`
3. Docker (مطلوب فقط لخدمات Postiz المحلية)

### 2) الاستنساخ والتثبيت

```bash
git clone https://github.com/Muhammed-Jameel/social-media-engine.git
cd social-media-engine
nvm install
nvm use
corepack enable
corepack prepare pnpm@11.19.0 --activate
pnpm install
cp .env.example .env.local
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm dev
```

انتقل إلى:

- لوحة التحكم: [http://localhost:3000](http://localhost:3000)

> يمكنك إضافة رابط فيديو شرح توضيحي هنا لاحقًا.

### 3) تشغيل الـ worker (في نافذة طرفية ثانية)

```bash
pnpm worker
```

## طريقة الاستخدام

### أ) الوضع المحلي الآمن (موصى به للتجربة الأولى)

1. أبقِ إعدادات الديمو مفعلّة.
2. استورد البيانات المحلية وشغّل خطة سبتمبر المولّدة.
3. راجع كل مسودة من خلال لوحة التحكم.
4. وافق أو عدّل قبل النشر.
5. تحقق من سجلات التدقيق وسجلات التشغيل.

### ب) نمط التشغيل اليومي

1. افتح لوحة التحكم.
2. فعّل إعادة توليد الخطة الشهرية أو راجعها.
3. مرّر العناصر عبر:
   - المسودة
   - المراجعة
   - الموافقة
   - النشر المراقب
4. نفّذ اختبارات ما بعد التشغيل ومراجعة الجودة.
5. حافظ على فصل واضح بين القياسات والأدلة.

### ج) للفرق والوكالات

1. احتفظ بنفس محرك الأساس.
2. حدّث `data/brand` بحقيبة أدلة علامتك.
3. اضبط قوالب المنشورات وأدوار الموافقة التي تناسب فريقك.
4. احرص على توافق ملفات الملكية والسياسة مع متطلبات الفريق.

## البيئة والإعدادات

### الإعدادات الآمنة المبدئية

- `DRY_RUN=true`
- `PRODUCTION_PUBLISHING_ENABLED=false`
- `DEMO_MODE=true`

هذه الإعدادات تمنع النشر الخارجي.

### نموذج النشر

هذا مشروع مفتوح المصدر ويمكن نشره بأي طريقة تناسب الفريق:

1. إعداد محلي فقط لبيئات الاستراتيجية/المراجعة الخاصة.
2. استضافة داخلية مشتركة لفرق موزعة صغيرة.
3. بنى إنتاج ذاتية الاستضافة بالبنية التحتية التي تفضلها.
4. أي بنية نشر مخصصة تدعمها مؤسستك.

موصلات المزوّدين متاحة ضمن نفس مجرى النشر مع متطلبات إضافية مرتبطة بالبنية المختارة.

### قائمة فحص البيئة

1. انسخ `.env.example` إلى `.env.local`
2. املأ فقط حقول التكامل التي أنت مستعد لاختبارها
3. لا تضع الأسرار في تاريخ Git
4. تأكد من إعدادات قاعدة البيانات والتشفير قبل التجارب الإنتاجية
5. شغّل فحص الأسرار قبل تفعيل أي موصل مزوّد

```bash
pnpm exec tsx scripts/check-secrets.mts
```

## إعداد النشر المراقب

فعّل هذا فقط بعد موافقة السياسات الداخلية.

1. اتبع [docs/setup/POSTIZ.md](docs/setup/POSTIZ.md)
2. شغّل خدمات Postiz:

```bash
pnpm postiz:up
```

3. أنشئ حساب مسؤول في: [http://localhost:4007](http://localhost:4007)
4. فعّل حساباتك وتطبيقات المزوّد.
5. عدّل مفاتيح النشر يدويًا:
   - `DRY_RUN=false`
   - `PRODUCTION_PUBLISHING_ENABLED=true`
   - `DEMO_MODE=false`
6. عد إلى تدفق المراجعة وانشر فقط العناصر المعتمدة.

## سير العمل والتشغيل

### التسلسل الشهري

1. استيعاب الاستراتيجية والـ brief
2. توليد المسودات (عربي + إنجليزي)
3. مراجعات إبداعية وجودة داخلية
4. حلّ بوابات الموافقة
5. تسليم المسودات/الجدولة
6. النشر المراقب
7. الاحتفاظ بالأدلة + القياس

### وضع الأمان

- مخرجات الذكاء الاصطناعي لا تنشر مباشرة.
- كل عملية إنتاج تتتبع بحالة المراجعة، وasset hashes، ومفاتيح عدم التكرار.
- التحليلات النموذجية موضوعة بوضوح كمؤشرات اصطناعية.
- إيقاف إجراءات المزوّد افتراضيًا.

### ملاحظات التشغيل

- استخدم `pnpm plan:september` لتحديث سير العمل المرجعي الحالي.
- أبقِ موافقات المالك مفعلة للمنشورات الحساسة.
- افحص كل تكامل عبر اختبارات القدرة والبيئة التجريبية قبل المرور الخارجي.

## خريطة المستودع

- `apps/web`: لوحة تحكم المالك للمراجعة والموافقات والسيطرة والتحليلات
- `apps/worker`: worker تنفيذ سير عمل متين
- `packages/schemas`: العقود المشتركة ونماذج النطاق
- `packages/db`: هجرات، مستودعات، ومنطق التخزين
- `packages/engine`: منطق خط الأنابيب والتنظيم
- `packages/observability`: سجلات منظمة وتلغيم سرية
- `skills`: تعليمات أدوار وسلوك خبراء المراجعة والجودة
- `data/brand`: أدلة العلامة والمرجعيات الأساسية
- `docs`: أدلة التشغيل والتنفيذ
